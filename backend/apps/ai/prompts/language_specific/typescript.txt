## TypeScript/JavaScript 语言专项审查指南

### 常见安全问题
- XSS：检查 dangerouslySetInnerHTML、innerHTML 使用是否经过净化
- 原型污染：检查 Object.assign、merge 操作对不可信输入的处理
- 供应链安全：检查第三方依赖的引入方式
- 敏感信息泄露：检查前端代码中是否硬编码 API Key、Token
- localStorage/sessionStorage 敏感数据存储

### 框架审查重点
- **React**: 检查 useEffect 清理函数、依赖数组完整性、key 属性使用、不必要的 re-render（memo/useMemo/useCallback）
- **Next.js**: 检查 Server Component 与 Client Component 划分、数据获取模式、API Route 安全性
- **Vue**: 检查 v-html XSS 风险、响应式数据丢失（解构 reactive 对象）、computed vs watch 使用场景
- **Node.js/Express**: 检查中间件顺序、错误处理中间件、请求体大小限制、CORS 配置

### 最佳实践
- 使用 strict 模式 TypeScript（tsconfig strict: true）
- 优先使用 interface 定义对象形状，type 用于联合/交叉类型
- 避免 any，使用 unknown 并进行类型收窄
- 异步操作使用 async/await，避免回调地狱
- 不可变数据更新（展开运算符），避免直接修改 state
- 使用 optional chaining（?.）和 nullish coalescing（??）
- 组件保持单一职责，Props 类型显式定义
