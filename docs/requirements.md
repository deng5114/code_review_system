# CodeReview Pro — 需求分析文档

> 版本: 1.0 | 日期: 2026-04-20

---

## 1. 项目概述

### 1.1 产品定位

CodeReview Pro 是一个本地部署的 AI 代码审查 Web 应用。开发者上传代码压缩包后，系统自动解析项目结构，使用多种 AI 模型进行代码审查，生成包含问题定位和修复建议的专业审查报告。

### 1.2 目标用户

- 个人开发者：在提交代码前进行自我审查
- 小型团队：作为代码审查的辅助工具
- 学习者：通过 AI 审查反馈学习编码最佳实践

### 1.3 核心价值

1. **零门槛**：上传压缩包即可审查，无需 Git 集成或 CI 配置
2. **多模型**：支持 OpenAI/Claude/Gemini/DeepSeek/Ollama 等，用户自带 Key
3. **多语言**：支持 TypeScript/Python/Go/Java/Rust/C++ 等主流语言
4. **可操作**：精确到行号的问题定位 + 具体修复建议 + 代码示例

### 1.4 参考项目

| 项目 | 借鉴内容 |
|------|---------|
| [everything-claude-code](https://github.com/anthropics/everything-claude-code) | 7维审查矩阵、4级严重性分级、多语言专项审查器、信心度过滤 |
| [PR-Agent](https://github.com/Codium-ai/pr-agent) | Diff 处理管道、Token 预算管理、多 LLM 统一接入、Prompt 模板系统、YAML 容错解析 |
| [Kodus AI](https://github.com/kodustech/kodus-ai) | 模型无关设计、CLI + Web 集成 |
| [ReviewScope](https://github.com/Review-scope/ReviewScope) | AST 静态分析 + AI 推理结合 |

### 2.2 详细功能描述

#### F1 — 项目上传与解析

**用户故事**: 作为开发者，我可以上传代码压缩包，系统自动识别项目类型和结构。

**验收标准**:
- [ ] 支持 .zip / .tar.gz / .tar.bz2 格式
- [ ] 上传后自动解压并解析文件结构
- [ ] 自动检测项目类型（基于配置文件）
- [ ] 显示语言分布统计
- [ ] 文件大小限制 100MB
- [ ] 自动排除 node_modules/, .git/, venv/, __pycache__/, dist/ 等目录
- [ ] 解压炸弹防护（总大小 1GB 上限，文件数 10000 上限）
- [ ] 路径穿越防护

**项目类型检测规则**:

| 配置文件 | 项目类型 |
|----------|---------|
| package.json | Node.js / TypeScript / JavaScript |
| tsconfig.json | TypeScript |
| pyproject.toml / setup.py / requirements.txt | Python |
| go.mod | Go |
| Cargo.toml | Rust |
| pom.xml | Java (Maven) |
| build.gradle / build.gradle.kts | Java / Kotlin (Gradle) |
| *.sln / *.csproj | C# / .NET |
| CMakeLists.txt / Makefile | C / C++ |
| pubspec.yaml | Dart / Flutter |
| Gemfile | Ruby |

#### F2 — AI 代码审查

**用户故事**: 作为开发者，我可以对上传的项目发起 AI 代码审查，获得多维度的问题分析。

**审查维度（7维矩阵）**:

| 维度 | 英文 | 检查项 |
|------|------|--------|
| 安全性 | Security | 硬编码密钥/API Key、SQL 注入、XSS、路径遍历、CSRF、不安全依赖、日志泄露 |
| 正确性 | Correctness | 逻辑错误、off-by-one、空值处理、边界情况、竞态条件、资源泄漏 |
| 性能 | Performance | N+1 查询、内存泄漏、无限循环、大载荷、缺失缓存、同步阻塞 I/O |
| 可维护性 | Maintainability | 大函数(>50行)、大文件(>800行)、深嵌套(>4层)、魔法数字、死代码 |
| 类型安全 | Type Safety | 类型不匹配、unsafe 转型、缺失泛型、any 滥用、隐式 any |
| 完整性 | Completeness | 缺失测试、缺失错误处理、不完整迁移、TODO/FIXME 无工单 |
| 最佳实践 | Best Practices | 命名规范、模式合规、语言惯用法、缺失文档、不一致的风格 |

**严重性分级**:

| 级别 | 含义 | 示例 |
|------|------|------|
| CRITICAL | 安全漏洞或数据丢失风险 | SQL 注入、硬编码密码、未验证的用户输入直接执行 |
| HIGH | Bug 或逻辑错误 | 空指针引用、竞态条件、资源泄漏、错误的算法 |
| MEDIUM | 质量问题或缺失最佳实践 | 大函数、缺失错误处理、缺失测试、魔法数字 |
| LOW | 风格建议或轻微改进 | 命名不一致、可简化的表达式、注释改进 |

**审查流水线（8 阶段）**:

```
Phase 1: 项目指纹识别
  → 检测语言、框架、依赖、代码统计

Phase 2: 文件分类过滤
  → 排除二进制、第三方、生成代码
  → 按语言优先级排序

Phase 3: Token 预算评估
  → 计算代码总量对应的 Token 数
  → 根据模型上下文窗口确定审查策略

Phase 4: 代码分片
  → Level 1: 全量审查（小项目）
  → Level 2: 分组审查（中项目）
  → Level 3: 分片审查（大项目）

Phase 5: AI 审查执行
  → 组装 Prompt（System + User + 语言专项）
  → 调用 AI 模型，获取结构化审查结果
  → 支持多 Chunk 并行

Phase 6: 结果聚合
  → 去重相同问题
  → 合并同类发现
  → 校验严重性分类

Phase 7: 报告生成
  → 生成总体评估摘要
  → 按严重性/维度/文件分组
  → 生成 Markdown 报告

Phase 8: 持久化存储
  → 保存到 SQLite
  → 通知前端更新
```

#### F3 — 审查报告展示

**用户故事**: 作为开发者，我可以在代码视图上看到行级别的问题标注，并查看详细的修复建议。

**页面组成**:

1. **审查摘要仪表盘**
   - 问题总数 + 严重性分布（CRITICAL/HIGH/MEDIUM/LOW 计数）
   - 维度分布图（7 个维度的热力图）
   - AI 总体评估文本
   - 项目概要信息

2. **代码查看器**
   - 左侧: 文件树（标注每个文件的问题数量）
   - 右侧: 代码视图（Monaco Editor 只读模式）
   - 问题行高亮 + 悬停显示问题卡片
   - 行号标注严重性颜色

3. **问题列表面板**
   - 按严重性排序的问题卡片列表
   - 每张卡片: 严重性标签 + 维度标签 + 文件路径:行号 + 问题标题
   - 展开后: 完整描述 + 修复建议 + 代码对比（问题代码 vs 修复代码）

4. **筛选面板**
   - 严重性多选: CRITICAL / HIGH / MEDIUM / LOW
   - 维度多选: 7 个维度
   - 文件筛选: 从文件树选择
   - 关键词搜索

#### F4 — AI 模型配置

**用户故事**: 作为开发者，我可以配置和管理我的 AI 模型 API Key，并选择默认模型。

**配置项**:

| 字段 | 说明 | 必填 |
|------|------|------|
| 提供商 | OpenAI / Anthropic / Google / DeepSeek / Ollama / OpenRouter | 是 |
| 显示名称 | 用户自定义名称 | 是 |
| API Key | 对应提供商的 API Key（Ollama 可不填） | 视提供商 |
| 模型名称 | 如 gpt-4o, claude-sonnet-4-6, gemini-pro | 是 |
| API 端点 | 自定义 base_url（Ollama 必填） | 否 |
| 默认配置 | 是否作为默认模型 | 否 |

**支持模型**:

| 提供商 | 推荐模型 | 适用场景 |
|--------|---------|---------|
| OpenAI | gpt-4o, o3 | 通用审查，性价比高 |
| Anthropic | claude-sonnet-4-6, claude-opus-4-7 | 深度分析，复杂推理 |
| Google | gemini-2.5-pro, gemini-2.5-flash | 快速审查，成本低 |
| DeepSeek | deepseek-chat, deepseek-coder | 国内友好，代码专项 |
| Ollama | qwen3, llama3, codellama | 本地部署，零成本 |
| OpenRouter | 多模型路由 | 灵活切换 |

#### F6 — 项目概览

**展示内容**:
- 项目类型和检测到的框架
- 文件树浏览器（可展开/折叠）
- 语言分布饼图
- 代码统计：文件数、代码行、注释行、空行
- 依赖列表（从 package.json / requirements.txt 等解析）

## 3. 非功能需求

### 3.1 性能要求

| 指标 | 目标 |
|------|------|
| 压缩包上传（50MB） | < 30 秒（含解析） |
| 小项目审查（< 20 文件） | < 60 秒 |
| 中项目审查（20-100 文件） | < 5 分钟 |
| 大项目审查（> 100 文件） | < 15 分钟 |
| 页面首屏加载 | < 2 秒 |
| API 响应时间（非审查） | < 500ms |

### 3.2 可靠性

- AI 调用失败时自动重试（最多 3 次）
- 支持模型降级（主模型失败切换备用模型）
- 上传中断可恢复
- 审查任务失败可重新发起

### 3.3 安全性

- API Key 加密存储（AES-256）
- 上传文件隔离存储
- 解压炸弹防护
- 路径穿越防护
- 文件类型白名单
- 定期清理过期文件

### 3.4 可用性

- 零配置启动（Django + SQLite，无需额外安装）
- 中文界面
- 响应式设计（支持 1280px+ 宽度）
- 审查进度实时更新

### 3.5 可扩展性

- 语言专项审查模块可插拔
- AI 模型提供商可扩展
- 审查维度可配置
- 自定义规则系统

## 4. 约束与假设

### 4.1 技术约束

- 前端: React + TypeScript
- 后端: Django + Django REST Framework
- 数据库: SQLite（单机部署）
- 无需 Redis（Celery 可使用 SQLite broker 或文件系统）

### 4.2 假设

- 用户自行准备 AI 模型的 API Key
- 本地部署，无需多租户支持
- 单用户使用场景
- 网络连接稳定（调用 AI API）

### 4.3 不包含

- Git 仓库集成（不支持直接分析 GitHub/GitLab 仓库）
- 多用户/团队协作
- 计费系统
- CI/CD 集成
- 实时协作审查
